# 詳細設計書：WorkoutForm 画面モジュール

## 1. ディレクトリ構成・配置定義
本画面機能に関連するソースコードは、以下のディレクトリ構成に従って配置される。

```text
workout/
├── components/
│   ├── ExerciseHistoryTable.tsx
│   ├── IntervalTimer.tsx
│   └── WorkoutFormInputs.tsx
├── hooks/
│   ├── useIntervalTimer.ts
│   └── useWorkoutForm.ts
├── utils/
│   └── workoutHelpers.ts
└── page.tsx
```

* **レンダリング方法**: クライアントコンポーネント (`'use client'`)

## 2. モジュール別詳細仕様

### 2.1 `ExerciseHistoryTable.tsx`（UIコンポーネント仕様）
選択された種目の過去実績データをグリッド形式で新しい順にレンダリングするコンポーネント。

#### 2.1.1 コンポーネント I/O (Props定義)
| Prop名 | 型 | 必須 | 説明 |
| :--- | :--- | :--- | :--- |
| `selectedExercise` | string | ◯ | 現在選択中の種目名。ヘッダーの動的表示に使用。 |
| `history` | `WorkoutSet[]` | ◯ | 選択種目の過去履歴データ配列。 |

#### 2.1.2 内部表示・レイアウト制御
1. **動的ヘッダータイトルの生成**
   - テンプレートリテラルを用いて、`selectedExercise` に値が存在する場合は `📌 {selectedExercise} の全記録` を表示し、空文字の場合は `📌 選択種目の全記録` とする。
2. **履歴テーブルのレンダリング条件**
   - `history.length > 0` の条件を満たす場合のみ、`<table>` 要素をDOMに構築する（データが0件の場合はヘッダータイトルのみ表示される）。
3. **アライメントおよびスタイル仕様**
   - テーブルのカラムは、視認性を高めるため以下のレイアウト調整をクラス定義（Tailwind CSS）で明示する。
     - **日付**: 左寄せ（`text-left`）
     - **ステータス**: 右寄せ（`text-right`）
     - **セット数**: 右寄せ（`text-right`）
     - **重量**: 右寄せ（`text-right`）
     - **レップ数**: 右寄せ（`text-right`）
   - データ行（`<tr>`）には `hover:bg-gray-50` を付与し、マウスポインタまたはタップ時のフィードバックを提供する。ループ時の `key` 属性には配列のインデックス（`idx`）を使用する。

### 2.2 `IntervalTimer.tsx`（UIコンポーネント仕様）
* 残り秒数を `分:秒`（秒側は `padStart(2, '0')` による2桁固定）に整形し、`font-mono` で中央表示する。
* クイック時間設定用に、2分(120s)、3分(180s)、5分(300s)、テスト用(5s)の4つのプリセットボタンを提供し、それぞれ `onSetPreset` ハンドラに秒数を引き渡す。

### 2.3 `WorkoutFormInputs.tsx`（UIコンポーネント仕様）
* 種目、ステータス、重量（0〜300kgの2.5kg刻み）、回数（1〜30回の1刻み）、備考、種目順序（`readOnly`）の入力を提供する。
* `status === 'メイン'` の場合のみ、セット番号入力フォームが動的にDOMレンダリングされる。
* 種目変更時には `onExerciseChange(value)` と `onSelectedExerciseChange(value)` を同時に発火させ、入力値と履歴表示を連動させる。

### 2.4 `useIntervalTimer.ts`（タイマー状態管理Hooks）
* 1秒（1000ms）周期でカウントを減算し、残り1秒以下でタイマーを自動停止。
* `navigator.vibrate([500, 300, 500])` によるバイブレーションと、`/sound/Cell_Phone.mp3` による音声通知を発火し、アンマウント時には `clearInterval` によるクリーンアップを確実に実施する。

### 2.5 `useWorkoutForm.ts`（フォーム・データ状態管理Hooks）
フォームの各種入力値ステートやマスタデータを管理。後述する各種Side Effects（自動補完や順序計算など）を司る。

### 2.6 `workoutHelpers.ts`（ユーティリティ・ヘルパー関数）

#### 2.6.1 `validateWorkoutForm`（バリデーション仕様）
フォーム送信時に実行される入力チェックロジック。以下のルールを順に検証し、1つでも不適合がある場合は処理を中断してエラーアラートを表示する。

| 入力項目 | チェック内容（バリデーションルール） | エラー時の表示メッセージ |
| :--- | :--- | :--- |
| **種目** | 未選択（空文字 `''`）でないこと | 「種目を選択してください」 |
| **ステータス** | 未選択（空文字 `''`）でないこと | 「ステータスを選択してください」 |
| **セット番号** | ステータスが「メイン」の場合のみ必須。<br>空文字でないこと、かつ1以上の整数であること。 | 「メインセットの場合はセット数を入力してください」 |
| **重量** | 未選択（空文字 `''`）でないこと | 「重量を選択してください」 |
| **回数** | 未選択（空文字 `''`）でないこと | 「回数（レップ数）を選択してください」 |

#### 2.6.2 `submitWorkoutData`（データインサート仕様）
* データをSupabaseへ送信する直前に、型コンバート処理を行う。
  - `weight`：文字列から数値（`Number`）にキャスト。
  - `reps`：文字列から数値（`Number`）にキャスト。
* ステータスが「メイン」**以外**（例：ウォーミングアップ、ディロードなど）の場合、`set_number` の値を強制的に `null` に上書きして送信する（DB側のデータ整合性を保つため）。

## 3. ライフサイクル・データフロー処理（Side Effects）

### 3.1 マスタデータ初期取得
* **トリガー**: コンポーネントマウント時。
* **処理フロー**: `exercises`（ID昇順）と `statuses`（ID昇順）をSupabaseから取得しステートを初期化。

### 3.2 種目順序（`exerciseOrder`）の自動設定
* **トリガー**: `exercise`, `status`, `today` 変更時。
* **処理フロー**: 当日に登録された全体のセット件数を `sets` テーブルから取得し、`カウント数 + 1` を自動設定して `WorkoutFormInputs` に読取専用として受け渡す。

### 3.3 メインセット自動値補完
* **トリガー**: `status`, `exercise`, `today` 変更時。
* **処理フロー**: `status === 'メイン'` かつ種目選択時のみ。過去最新のメインセットから重量（`weight`）を自動補完し、さらに今日の同種目メインセット件数をカウントし、`カウント数 + 1` を `setNumber` に自動設定。

### 3.4 選択種目履歴の取得
* **トリガー**: `selectedExercise` または `historyTrigger` 変更時。
* **処理フロー**: 選択された種目の過去全データを `date` 降順、かつ同一日内は `set_number` 昇順で取得し履歴ステートを更新して `ExerciseHistoryTable` に受け渡す。

## 4. 主要イベント処理

### 4.1 記録保存処理（`page.tsx` 内 `handleSubmit`）
ユーザーによる「記録する」ボタンクリック時の非同期処理。

1. **バリデーションの実行**: `validateWorkoutForm(...)` を呼び出す。不適合の場合はエラーアラートを表示して強制終了。
1. **データ保存要求**: `submitWorkoutData(...)` を実行。失敗時はエラー詳細をアラート表示して終了。
1. **保存成功後の処理**: 成功アラートを表示。`refreshHistory()` を実行（`historyTrigger` カウンターを加算）し履歴表示を最新化。`reps` (レップ数入力) の選択状態をクリア（`''`）にする。
1. **「メイン」セット時の連動処理**:
   - 現在の `status` が `'メイン'` の場合のみ以下を実行：
     - **セット番号の更新**: `setSetNumber(prev => String(Number(prev) + 1))` により次のセット番号へと自動インクリメント。
     - **タイマーの連動自動化**: インターバルタイマーをリセット（`resetTimer()`）した直後に、自動でカウントダウンを開始（`startTimer()`）させる。
