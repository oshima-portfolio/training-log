# 業務ルール・ロジック定義書 (rules)

本ドキュメントは、「Training Log」アプリケーションに実装されている特有のビジネスロジック、自動化ルール、データ計算およびバリデーションの仕様について説明します。

---

## 1. 短時間用筋トレ (ドロップセット) 重量自動調整ルール

短時間用筋トレ記録画面（`/dropset`）では、設定された種目ごとの目標回数（レップ数）のクリア状況に応じて、次回セッションの重量がシステムによって自動的に増減（プログレッシブオーバーロードの自動化）されます。

### ロジック詳細
実施したレップ数 (`reps`) を、ルーチンに定義された昇格しきい値 (`threshold_reps`) および降格しきい値 (`demotion_threshold`) と比較します。

```mermaid
flowchart TD
    Start([レップ数入力]) --> Decision{レップ数判定}
    
    Decision -- "reps >= 昇格しきい値 (成功)" --> Success[consecutive_success +1<br>consecutive_failure = 0]
    Decision -- "reps < 降格しきい値 (失敗)" --> Failure[consecutive_failure +1<br>consecutive_success = 0]
    Decision -- "上記以外 (維持)" --> Keep[consecutive_success = 0<br>consecutive_failure = 0]
    
    Success --> SuccessCheck{consecutive_success >= 2 ?}
    SuccessCheck -- Yes --> UpWeight[重量 +2.5kg<br>consecutive_success = 0<br>メッセージ: 🎉 重量アップ！]
    SuccessCheck -- No --> End[終了 / 重量変更なし]
    
    Failure --> FailureCheck{consecutive_failure >= 2 ?}
    FailureCheck -- Yes --> DownWeight[重量 -2.5kg (下限0kg)<br>consecutive_failure = 0<br>メッセージ: 📉 重量ダウン...]
    FailureCheck -- No --> End
    
    Keep --> End
    UpWeight --> End
    DownWeight --> End
```

- **【成功】**: レップ数 $\ge$ 昇格しきい値 (`threshold_reps`)
  - `consecutive_success` を `+1`、`consecutive_failure` を `0` にリセット。
  - `consecutive_success` が **2回** に達した場合、設定重量を **`+2.5kg`** アップし、カウンタを `0` にリセット。
  - 通知メッセージ: `🎉 重量アップ！ [旧重量]kg -> [新重量]kg`
- **【失敗】**: レップ数 $<$ 降格しきい値 (`demotion_threshold`)
  - `consecutive_failure` を `+1`、`consecutive_success` を `0` にリセット。
  - `consecutive_failure` が **2回** に達した場合、設定重量を **`-2.5kg`** ダウン（下限 0kg）し、カウンタを `0` にリセット。
  - 通知メッセージ: `📉 重量ダウン... [旧重量]kg -> [新重量]kg`
- **【維持】**: 上記のいずれにも該当しない場合（例: 降格しきい値 $\le$ レップ数 $<$ 昇格しきい値）
  - `consecutive_success` と `consecutive_failure` をともに `0` にリセット。重量の変更は行いません。

## 2. 部位別経過日数（トレーニング頻度）計算ルール

ダッシュボード（`/`）で表示される「トレーニング頻度」は、過去の全記録から各部位の最終トレーニング日を特定し、今日までの経過日数を算出します。

### 2.1 部位特定ルール (BIG3優先ルール)
種目名から対象部位（カテゴリ）を判定する際、以下の **BIG3優先オーバーライド** がハードコードで適用されます。

| 種目名 | 優先判定部位 | 備考 |
| :--- | :--- | :--- |
| **ベンチプレス** | **胸** | 種目マスタのカテゴリ設定に関わらず「胸」として判定 |
| **デッドリフト** | **背中** | 種目マスタのカテゴリ設定に関わらず「背中」として判定 |
| **スクワット** | **脚** | 種目マスタのカテゴリ設定に関わらず「脚」として判定 |

*※上記以外の種目は、`exercises` マスタテーブルの `category` フィールドの値がそのまま適用されます。*

### 2.2 経過日数の算出と表示順
1. **最終実施日の特定**: 部位ごとに、`sets` テーブルに存在する最新の `date` を特定します。
2. **経過日数の計算**: 今日 (`todayStr`) と最終実施日の差分を日付単位で算出します。
   $$\text{経過日数} = \lfloor \frac{\text{今日(タイムスタンプ)} - \text{最終実施日(タイムスタンプ)}}{1000 \times 60 \times 60 \times 24} \rfloor$$
3. **並び替え**: 経過日数が**長い順（降順）**にソートして表示します（長くトレーニングしていない部位がテーブルの上位に表示されます）。

## 3. 筋トレ記録における自動入力ルール

筋トレ記録画面（`/workout`）では、入力の手間を減らすための自動入力アシスト機能が動作します。

### 3.1 メインセット選択時の自動補完
ユーザーが画面で「種目」を選択し、「ステータス」に **「メイン」** を指定した際に以下の自動入力が行われます。

- **前回重量の引き継ぎ**:
  - `sets` テーブルから、同一種目の過去の記録（ステータスが「メイン」のもの）を日付の降順で検索し、最も新しい日付の `weight` を「重量」入力欄に自動設定します。過去に該当種目のメインセット記録がない場合は空欄になります。
- **セット数のインクリメント**:
  - `sets` テーブルから、**今日（当日）**の同一種目のメインセット数をカウントし、それに **`+1`** した値を「セット数」入力欄に自動設定します（例: 今日すでに2セット記録していれば、自動で「3」が入力される）。
- *※ステータスが「メイン」以外（例: 「UP」など）の場合は、上記自動補完は行われません。*

### 3.2 種目順序 (exercise_order) の自動採番
- ユーザーが画面で値（種目、ステータス、重量、レップ、日付）を操作するたびに、今日登録されたセットの総数を `sets` テーブルからカウントし、それに **`+1`** した値を `exercise_order` として自動設定します。
- これにより、その日に登録した順番が自動的に維持されます。

### 3.3 タイマー自動連動
- ステータスが「メイン」のセットの記録ボタンを押して登録が成功した際、自動的にインターバルタイマーがリセットされ、カウントダウンが開始されます。

## 4. 体重データの比較・平均計算ルール

体重記録画面（`/weight`）では、日々の体重推移の傾向を掴みやすくするため、前週・先月との比較、および月別の平均を計算して表示します。

### 4.1 前週比の計算
単なる「7日前」の体重との比較ではなく、**「前週の平均体重」**との差分を計算します。
- **前週の対象期間**: 基準日（対象レコードの日付）の **`8日前 〜 2日前`** の範囲（1週間前を中心とした7日間）。
- **ロジック**:
  1. 上記期間内に存在する体重記録の平均値を計算します。
  2. `基準日の体重 - 前週の平均体重` を算出し、小数点第1位まで表示します。期間内にデータが1件もない場合は比較値は表示されません (`null`)。

### 4.2 先月比の計算
単なる「30日前」の体重との比較ではなく、**「先月の月間平均体重」**との差分を計算します。
- **先月の対象期間**: 基準日の **`前月1日 〜 前月末日`** の範囲。
- **ロジック**:
  1. 先月の期間内に存在する体重記録の平均値を計算します。
  2. `基準日の体重 - 先月の平均体重` を算出し、小数点第1位まで表示します。先月のデータがない場合は比較値は表示されません (`null`)。

### 4.3 月別平均体重の集計
- すべての体重データを年・月（`YYYY-MM`）ごとにグループ化します。
- 各月ごとの平均値（`合計体重 / 測定日数`）を算出し、**新しい月順（降順）**でソートして一覧表示します。

## 5. グラフデータ集計ルール

データ分析画面（`/chart`）では、期間フィルター（全期間 / 3ヶ月 / 6ヶ月 / 1年）および集計モード（日別 / 週別 / 月別）に応じて、以下のロジックで集計したデータをグラフにプロットします。

### 5.1 グラフタイプ別の計算ロジック
- **総負荷量 (volume)**:
  - 期間内の全セットについて、$\sum(\text{重量} \times \text{回数})$ を計算します。
- **最大重量 (maxWeight)**:
  - 期間内の全セットにおける $\max(\text{重量})$ を抽出します。
- **推定1RM (estimatedMax)**:
  - 各セットについて以下の **Epley式** で推定1RMを算出し、その期間内での最大値を抽出します。
    $$\text{推定1RM} = \begin{cases} \text{重量} & (\text{回数} = 1) \\ \text{重量} \times (1 + \frac{\text{回数}}{30}) & (\text{回数} > 1) \end{cases}$$
- **セット数 (setCount)**:
  - 期間内に実施されたセット数（レコード件数）をカウントします。

### 5.2 集計単位 (グループ化) ルール
集計キーを以下のフォーマットに変換してデータをグループ化します。
- **日別 (daily)**: `YYYY-MM-DD`
- **週別 (weekly)**: `YYYY-W##` (ISO週番号)
- **月別 (monthly)**: `YYYY-MM`

## 6. バリデーションルール

### 6.1 筋トレ記録フォーム入力制限
記録登録時、以下のバリデーションが適用されます。

| 項目 | 必須チェック | 条件・仕様 |
| :--- | :---: | :--- |
| **種目** | **必須** | 未選択の場合は登録エラー |
| **ステータス** | **必須** | 未選択の場合は登録エラー |
| **重量** | **必須** | 未入力の場合は登録エラー |
| **回数** | **必須** | 未入力の場合は登録エラー |
| **種目順序** | **必須** | 自動設定されるため、基本的には常に存在する |
| **セット数** | **条件付き必須** | **ステータスが「メイン」の場合のみ必須**（UP等の場合は空欄を許容し、DBにはNullとして登録される） |
